Add fastb engine with look and chunk runner (phases 1 and 2)

Phase 1, engine skeleton:
- Background engine on a local socket, started by a thin CLI on demand.
- Browser: own Chrome profile (optional headless, optional --fresh temporary
  profile) or a running Chrome over CDP; options stick until changed.
- look: compact page text with refs (@e3) from Playwright's AI aria snapshot,
  about 6x smaller than the raw snapshot on a REAL benchmark page. Rich-text
  editors are marked as textboxes so they get refs.
- Settle: wait for a quiet DOM and no visible loading indicator, never
  "network idle".

Phase 2, chunks:
- fastb run: many steps in one call (heredoc, file or arguments), stops at
  the first surprise with the step, the reason and the page.
- Target finder: refs, labels, roles, text, with HTML fallbacks; ambiguous
  targets stop with a numbered list of choices.
- REAL gomail-3 passes the benchmark checker with one 6-step chunk in 0.9 s.

Also: project docs, plan, baseline results and shared agent rules (AGENTS.md).
